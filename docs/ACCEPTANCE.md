# Acceptance evidence

This table maps the seventeen acceptance criteria (A1 to A17) of the product specification to the evidence that exists in this repository. The specification itself is not published; each criterion is summarized in the table below, which is enough to read the evidence against it. Evidence kinds:

- **Test**: an automated test, named `file:TestName`. Integration tests run against PostgreSQL 16 as the `app_user` runtime role. `make test` runs everything with `go test ./... -race -count=1 -p 1` and needs `TEST_DATABASE_URL` and `TEST_DATABASE_OWNER_URL`.
- **Script**: `scripts/e2e.sh` (ten-step core proof against a running dev server with `DEV_LOGIN_BYPASS=1` and the `local-test` OAuth client; 31 of 31 checks passed locally), `scripts/loadcheck.sh` (bounded load check), `scripts/screenshots.mjs` (headless Chrome screenshots; needs Google Chrome on macOS and Node 22 or newer).
- **Manual**: a procedure a person performed, with the date where known.
- **BLOCKED / NOT VERIFIED**: nothing in this repository exercises the criterion, and why.

Status values: PASS (automated or scripted evidence exists and passed locally), MANUAL (performed by hand), PARTIAL (some sub-claims covered, the rest listed), BLOCKED.

## Blueprint compliance review (2026-09-18)

An independent adversarial review against `blueprint/claude.md` and the core pattern files audited every non-test source file. It found no Critical issues. What was fixed in response:

- Tenant scope now has two documented entry points only: `db.WithTenant`/`WithTenantSerialized`/`WithTenantSnapshot`, and `db.EnterTenantScope` for the signup transaction that creates the tenant. `make check` fails if `EnterTenantScope` is called anywhere else, if the SECURITY DEFINER token lookups are called outside the credential models, or if a controller or the MCP adapter touches the database handle.
- Request-ID middleware runs first; `POST /logout` is CSRF-protected; share-link management routes are rate limited; the startup OAuth client sync is an atomic upsert; MCP mutation logs carry entry IDs, not paths.
- Every user-visible string in templates, JavaScript, controllers and models goes through the catalog (299 keys). Inline styles were removed (the CSP had blocked them anyway). Preview fragments render through `partials/_preview.html` instead of string-built HTML.
- Migration 5 adds `updated_at` with triggers to every table whose rows are mutated after insert.
- `.github/workflows/ci.yml` runs gofmt, vet, `make check`, the full test suite against PostgreSQL as the runtime role, and a migration down/up round trip.

Deviations kept on purpose, with the reason:

| Blueprint rule | Deviation | Reason |
|---|---|---|
| Sessions 24h max | 30-day sessions | The product specification proposes 30 days (section 7); logout revokes immediately. |
| Bootstrap only, `app.css` under 100 lines | `site.css` (themes) and `landing.css` (marketing page) define their own classes | The specification requires two rendered-site themes with light/dark modes and a public landing page; Bootstrap components cannot express them. The dashboard itself is Bootstrap with an 11-line `app.css`. |
| No RLS bypass from request code | Four narrow `SECURITY DEFINER` lookups resolve a token hash to tenant and status before a scope exists | Required by the specification (section 6). They return identifiers only, never content, and `make check` pins their call sites. Migration 8: the five credential tables let the owner role (`app_owner`, which the lookups execute as) read rows without a tenant scope, because on a managed database that role has no `BYPASSRLS` and the lookups otherwise return nothing. The runtime role stays tenant-confined everywhere; `TestCredentialLookupsWorkWithoutBypass` pins the policy shape. |
| Language detection middleware | Language fixed to `en` | English-only ship; the catalog is complete so a second language is a detection middleware away. |
| Files about 300 lines | 15 files exceed it, the largest 650 lines | Deferred; splitting is mechanical and planned. |
| No custom JavaScript | 3 small files (copy buttons, appearance toggle and drafts, landing typewriter) | Under 100 lines total, no inline scripts, all degrade without JavaScript. |
| Project configuration `ai: false`, `jobs: false` | `internal/platform/ai` calls the Anthropic Messages API from `models.SuggestPlacement` | One bounded synchronous classification (8 s timeout, 300 output tokens, per-tenant hourly budget) inside a read-only operation, with a deterministic fallback so the feature works with no key. No agent loop, no background job, no stored model output; every call is audited in `ai_call` (RLS, no content). `POST /organize`, `tmp_organize` and `tmp_write` path `auto` are additive. |
